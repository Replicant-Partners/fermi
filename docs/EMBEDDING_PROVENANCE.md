# Embedding Provenance

**Status:** Phase 1 landed (2026-06-12).
**Spec:** [docs/specs/22_EMBEDDING_PORTABILITY_SPEC.md](specs/22_EMBEDDING_PORTABILITY_SPEC.md).
**Backfill notes:** [docs/EMBEDDING_PROVENANCE_BACKFILL_NOTES.md](EMBEDDING_PROVENANCE_BACKFILL_NOTES.md).

---

## What this is

A discipline: **every vector written to the database is stored with the exact text that produced it plus full model provenance.** If a vendor deprecates a model or raises prices, we re-embed the source text under a new model. Lossless. No exotic translation method needed.

The discipline is enforced by:

1. The `ProvenancedEmbedding` Rust type — call sites that persist vectors MUST go through `EmbeddingGenerator::generate_provenanced()` and pass the resulting struct to a `_with_provenance` storing function.
2. The `embedding_provenance` append-only sidecar table — a separate event row is written for every embedding ever generated.
3. The CI test `test_mock_embedder_round_trip` — proves that the captured provenance is sufficient to reproduce the vector from `source_text` alone.

---

## The four fields per embedding

Stored on each row of `episodes`, `semantic_rules`, `entities`, `communities`, `shopping_profiles` AND on each event row in `embedding_provenance`:

| Field | Type | Purpose |
|---|---|---|
| `embedding_model_id` | TEXT | `"<provider>/<model>"` — globally unique. e.g. `"anthropic/voyage-2"`. |
| `embedding_model_version` | TEXT | Manual epoch, e.g. `"2024-01-01"`. Bumped in code on observed drift. |
| `embedding_dim` | INTEGER | Output dimensionality. Guards against silent model swaps. |
| `source_text` | TEXT | The EXACT text passed to the embedder. NULL only for centroid embeddings (communities, shopping_profiles). |

Plus the existing `agent_id` / `created_at` columns, and a new `source_ref JSONB` capturing the caller's context (e.g. `{"kind":"execute_handler", "agent_id": "..."}`).

The `provenance_trusted BOOLEAN` flag distinguishes between vectors we wrote ourselves (TRUE) and vectors imported from clients or reconstructed by backfill (FALSE).

---

## Two storage locations

### Per-row columns (denormalised, cheap queries)

The 6 columns above live directly on each vector-bearing table. This is the "what produced the CURRENT vector" view — convenient for joins and ad-hoc queries.

### `embedding_provenance` append-only sidecar (the source of truth)

A separate event table. Every embedding write — initial, backfill, re-embed, fork — INSERTS a new row here. Re-embeds also UPDATE the per-row columns on the target table; the sidecar preserves the FULL history.

```sql
CREATE TABLE embedding_provenance (
    provenance_id UUID PRIMARY KEY,
    target_table  TEXT NOT NULL,          -- which table
    target_id     UUID NOT NULL,          -- which row
    agent_id      UUID,
    user_id       TEXT,
    source_text   TEXT,                   -- NULL for centroids
    source_ref    JSONB,
    model_id      TEXT NOT NULL,
    model_version TEXT NOT NULL,
    dim           INTEGER NOT NULL,
    embedding     vector(1024),           -- vector AT this point in history
    trusted       BOOLEAN NOT NULL,
    created_at    TIMESTAMPTZ NOT NULL,
    notes         TEXT                    -- "initial_write", "backfill", etc.
);
```

UPDATE and DELETE are REVOKED from PUBLIC. The table is append-only at the database level.

## The `provenance_trusted` flag

| Value | Meaning |
|---|---|
| `TRUE` | Generated by our own pipeline via `generate_provenanced()`. Source text was passed to a real embedder and bundled with its identity in the same call. |
| `FALSE` | Either (a) client-imported via `import_embeddings_handler` (model identity is asserted but unverifiable) or (b) backfilled from pre-Spec-22 rows where `source_text` reconstruction may be lossy. |

The re-embed worker (Phase 3) treats untrusted rows as eligible for opportunistic verification: when re-embedding, the worker re-derives the vector from `source_text` on the CURRENT model, compares cosine similarity, and flips the flag to TRUE only if it matches. If it doesn't, the row stays untrusted and is flagged for review.

## Model version policy

**Vendors do not expose stable embedding-model version strings via their APIs.** We capture `model_version` as a manual `"YYYY-MM-DD"` epoch managed by constants in [`agent-bestiary/memory/src/embeddings.rs`](../agent-bestiary/memory/src/embeddings.rs):

```rust
const VOYAGE_MODEL_VERSION:  &str = "2024-01-01";
const OPENAI_EMBED_VERSION:  &str = "2024-01-01";
const MISTRAL_EMBED_VERSION: &str = "2024-01-01";
const QWEN_EMBED_VERSION:    &str = "2024-01-01";
const MOCK_EMBED_VERSION:    &str = "mock-v1";
```

Bump these when:

- We observe quality drift on benchmarks.
- A vendor announces a model update.
- We switch to a measurably different model snapshot.

Bumping a version string is the trigger for the re-embed worker (Phase 3 of Spec 22) to refresh existing vectors stamped with the old version.

## How call sites write embeddings

Required pattern at every persistence call site:

```rust
// 1. Build the source_text ONCE.
let embed_text = format!("{} {}", query, reasoning.unwrap_or(""));

// 2. Embed and bundle provenance in a single call.
let provenance = state.embedder.generate_provenanced(&embed_text).await.ok();

// 3. Provide a source_ref capturing caller context.
let source_ref = serde_json::json!({
    "kind": "execute_handler",
    "agent_id": agent_id,
});

// 4. Persist via the _with_provenance variant.
state.memory_store
    .store_episode_with_provenance(episode, provenance.as_ref(), Some(source_ref))
    .await?;
```

The compiler enforces this discipline: the old `store_episode()` / `store_semantic_rule()` / etc. functions are marked `#[deprecated]` so any new use surfaces as a warning. The replacement variants (`store_episode_with_provenance` etc.) take a `ProvenancedEmbedding` and write the per-row provenance columns AND the sidecar event row in a single transaction.

For paths that legitimately defer embedding (synthetic correction episodes, composition rejections, simops actuation plans), pass `provenance=None` — the row is stored with NULL provenance and is identifiable for later opportunistic embedding via its `source_ref.kind`.

## Read-only embedding paths

Two query-embedding paths use `generate()` directly (no persistence):

- `src/agent_backend/kg_context.rs:57` — query embedding for KG cosine retrieval
- `src/agent_backend/tools_legacy.rs:2124` — `search_knowledge` tool

These MUST use the same model as the rows they compare against. The single shared `state.embedder` enforces this at runtime: cosine similarity between query and persisted vectors is only meaningful if both came from the same `model_id`. If a future migration introduces multi-model retrieval, the read paths will need to switch embedders per target row.

## Closed-model anchor set (Phase 2)

**Status:** Phase 2 landed (2026-06-12).

The anchor set is the cheap standing hedge against vendor deprecation. A fixed collection of ~3000 texts is co-embedded against:

1. **Every vendor model in active use** (`anthropic/voyage-2`, etc.) — `vector(1024)`.
2. **Our reference open model** — `nomic-embed-text-v1.5`, `vector(768)`. Self-hosted via Ollama, vLLM, llama.cpp server, or a Python sidecar. The reference side never depends on any vendor.

If a vendor goes dark — model deprecated, key revoked, prices doubled — the (vendor, reference) anchor pairs are sufficient to fit a Tier 2 translator that carries orphaned vendor vectors forward. Without standing anchors, that translator cannot be fit post-hoc because the dead vendor model is unreachable. With them, the translator costs a few hundred lines of linear algebra.

### Reference open model deployment

The `NomicEmbeddings` Rust client speaks the OpenAI-compatible embeddings API. Any endpoint that implements it works:

| Deployment | Endpoint | Notes |
|---|---|---|
| **Ollama** (recommended) | `http://localhost:11434/v1/embeddings` | `ollama pull nomic-embed-text && ollama serve`. Zero-config. |
| Python sidecar | configurable | FastAPI + sentence-transformers (`pip install sentence-transformers`). More setup, more control. |
| vLLM / llama.cpp server | configurable | For higher throughput. |
| Nomic hosted API (atlas.nomic.ai) | configurable | Defeats the purpose — it's a vendor again. **Not recommended.** |

The client reads `NOMIC_BASE_URL` and `NOMIC_API_KEY` env vars. Default base URL is Ollama's local endpoint.

### Anchor composition

A `target_size=3000` seed produces this default distribution (see `scripts/embedding_anchors.rs`):

| Bucket | Share | Source |
|---|---|---|
| `episode` | 35% | Sampled from production `episodes.source_text` (trusted rows) |
| `rule` | 20% | Sampled from active `semantic_rules.rule_content` |
| `entity` | 20% | Sampled from non-invalidated `entities.entity_name` + summary |
| `external` | 25% | Built-in diversity list — Wikipedia summaries, technical RFCs, multilingual samples |

Tune via `--share-episodes`, `--share-rules`, `--share-entities`, `--share-external` (must sum to 1.0).

### Operating the anchor set

```bash
# 0. Stand up the reference model (one-time, host machine):
ollama pull nomic-embed-text && ollama serve

# 1. Initial seed — embed every anchor on the reference model:
cargo run --bin embedding-anchors -- seed --target-size 3000 --confirm

# 2. Refresh vendor side for all active vendor models:
cargo run --bin embedding-anchors -- refresh --confirm

# 3. Report coverage:
cargo run --bin embedding-anchors -- status
```

Refresh policy:

- A vendor's side is recomputed when the vendor's `model_version` is bumped in code (model drift suspected).
- On a 7-day staleness window (configurable via `--max-age-days`).
- On demand via `refresh --force --confirm`.

The reference side is recomputed only when `NOMIC_EMBED_VERSION` is bumped in code.

### Cost ceiling

5000 anchors × N vendor models × refresh-on-version-change = a few thousand vendor API calls per quarter, in practice. At Voyage-2 prices this is <$1/quarter per vendor model. Cheap standing insurance.

### Vendor deprecation detection

Not yet automated. The intended check: a periodic `embedder.generate("ping").await` against each vendor model in use; on specific HTTP signatures (404 on the model endpoint, 410 Gone, deprecation header) trigger an alert. Anchors are already in place; the Tier 2 translator can be fit post-hoc from them. **Open work item.**

## What was deferred

- **Phase 1b — backfill of pre-Spec-22 rows.** A standalone binary stamps existing rows with `provenance_trusted=false`. Run once per environment after Phase 1 lands.
- **Phase 1c — NOT NULL constraint.** After backfill completes, an `ADD CONSTRAINT NOT VALID ... VALIDATE` migration enforces "if embedding IS NOT NULL then full provenance IS NOT NULL" as a database invariant.
- **Phase 3 — re-embed worker.** Built at first real model switch.
- **Phase 4 — embedding cache.** Keyed on `(model_id, model_version, sha256(source_text))`.
- **Phase 5 — Similarity Lab.** Per-pair fidelity metrics for migration acceptance gates.
- **Phase 6 — Tier 2 translator.** Hedged for the closed-model gap only.

See [Spec 22](specs/22_EMBEDDING_PORTABILITY_SPEC.md) for triggers and detailed plans.
