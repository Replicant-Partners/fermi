Architecture overview
Social Agent Observability Platform
A four-plane architecture for observing long-running social agents that evolve and personalise over time. Episode-level evaluation feeds upward into longitudinal tracking; human interventions feed back down through the coherence agent — closing the loop.

Accumulates relational state per human–agent dyad across sessions. Records rapport, reciprocity, trust evolution, and relationship rupture events. This is the primary source for the observatory dashboard's social arc charts. Feeds into the agent timeline store keyed by (agent_id, human_id, session).

Computes persona drift by embedding agent outputs at each persona_version and computing cosine distance between versions. Also tracks value-laden language shift (trust language, hedging, assertiveness) as qualitative signal. High variance in rolling std is itself an anomaly signal — not just low scores.

Writes per-episode verdicts to the agent timeline store including the aggregated score, per-dimension scores, conflict flags, and routing decision. This is what the trend analyser and anomaly detector consume.

Surfaces the agent timeline store visually. Shows: per-agent persona arc over time, drift vector magnitude chart, social capital curves per dyad, evaluator agreement/conflict history, and live anomaly feed. Two triggers into HITL queue: anomaly events from the detector, and evaluator conflicts from the registry.

Receives flagged episodes from two sources: anomaly detector (longitudinal drift events) and evaluator registry (per-episode conflicts). Reviewer sees: episode transcript, per-evaluator score breakdown, judge explanation, conflict highlighting. Three actions: approve (confirms verdict), relabel (corrects scores), intervene (substantive correction triggering full feedback flow).

The output of a reviewer intervention. Encoded as a high-authority EpisodeBundle with provenance: HumanAuthority and confidence: 1.0. Carries dimension, scope, correction, and belief-vs-behaviour classification. Enters the coherence agent — not as a database patch but as a structured signal subject to the same coherence check as any other episode.

scope: agent-wide ⚠
Episode — annotates single record only. No relationship or persona update. Use for isolated incidents.
Dyad — updates relationship state for this human–agent pair. Persona baseline unchanged. Use for relationship-specific issues.
Agent-wide — updates persona baseline and belief model globally. Requires two-reviewer consensus. Most destructive scope — use only for confirmed systemic drift.
3
Coherence check — contradiction scan
minimum update set · tension flagging · no silent overwrites
coherence
Three checks run before any write. The coherence agent determines minimum update set — only that set is updated, never everything downstream.

Belief revision

Agent held incorrect belief. Target: world model, relationship beliefs, factual grounding.

Behavioural correction

Agent acted wrongly despite correct beliefs. Target: action tendencies, response style.

→ world model + relationship beliefs updated. Action tendencies unchanged. Overwriting action tendencies here would cause the agent to lose correct behavioural patterns.
→ action tendencies + response style updated. World model unchanged. Overwriting beliefs here would cause the agent to forget correct knowledge about the relationship.

  • corrections[] field appended

Write 2 — Synthetic episode

  • Corrected version of interaction
  • provenance: human_corrected
  • authority: HumanAuthority (max)

  • Not overridable by lower-conf signals

↺ loop
The next episode generated by this agent is evaluated against the updated persona baseline. The drift monitor now has a corrected checkpoint. The synthetic episode participates in the episodic learning loop at full HumanAuthority weight — it cannot be averaged down by subsequent lower-confidence observations. The full loop from agent capability → evaluator registry → longitudinal store → human surface → coherence agent → episodic memory is now closed.
